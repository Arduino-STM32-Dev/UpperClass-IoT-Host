# Хост верхнего уровня (上位机) для промышленного IoT

Это **частная проектная записка** о продукте **верхнего уровня** (supervisory host / верхний компьютер): слой над полевыми устройствами, который превращает сырые OT-кадры в данные, пригодные для эксплуатации, отображения и команд.

Репозиторий описывает только направление хост-слоя. Он **не** документирует, не форкает и не раскрывает существующий полевой проект.

## Ядро R&D: зачем связь хоста верхнего уровня с новой PCB

С точки зрения разработки первый жёсткий барьер — не красота HMI, а **замкнутый контур между хостом верхнего уровня и новой PCB**. Пока контур красный, прошивка, протокол и продуктовые обещания не доказаны.

**Что значит установить связь**

1. **Доказать контракт протокола** — «В сети» не значит TCP connect. Связь есть, когда декодер хоста принял кадры с согласованными стартовыми байтами, адресом (`A` + `CA`), контрольной суммой и картой TI.
2. **Отделить bring-up железа от облачных демо** — Первый спин платы должен говорить с *нашим* хостом, а не с MQTT-игрушкой вендора. Диалект, таблица точек и семантика команд остаются под контролем R&D.
3. **Сделать идентичность долговечной** — 4G IP меняется; адрес канала / общий адрес — нет. Регистрация на хосте превращает новую плату в именованный актив в лаборатории и затем в поле.
4. **Получить поверхность регрессии** — Когда хост принял плату, каждое изменение прошивки оценивается: время handshake, завершение GI, ненулевые YX/YC, метка SOE, удержание heartbeat.
5. **Открыть остальной стек** — Архив, аварии, Web API, мобильный экран и ДУ бесполезны, пока путь по проводу не реален.

**Что становится возможным после успешной связи**

| Возможность | Результат для R&D |
|---|---|
| Инициализация канала + детект диалекта | Подтвердить путь balanced / standard 101 (или custom) на этой ревизии PCB |
| Общий опрос (GI) | Полный снимок YX/YC проверяет таблицу точек и разводку ADC/IO |
| COS / SOE | Доказать путь событий и качество часов для защитных сигналов |
| Синхронизация / чтение часов | Выровнять время платы, чтобы SOE было пригодно для разбора |
| Выбор → исполнение → отмена | Безопасный путь удалённой команды для объектов выключателя на новой плате |
| Heartbeat / reconnect | Измерить hold, drop rate и восстановление под NAT и 4G |
| Persist + API | Та же сессия кормит архив и ops UI без второго протокола |
| Многоплатный soak | Параллельные сессии рано ловят гонки, буферы и коллизии адресов |

**Стоп-условие R&D для спина PCB:** в списке хоста плата online с верным диалектом; GI даёт непустые YC/YX; минимум один round-trip COS/SOE; сухой прогон команды OK; сессия держится через heartbeat. Только после этого плата уходит из «лабораторного провода» в продуктовую интеграцию.


## Зачем нужен хост верхнего уровня

Платы, FTU, ПЛК и датчики говорят короткими двоичными кадрами по UART/TCP. Операторы — нет. Хост верхнего уровня — сторона диспетчерской, которая:

1. Принимает много одновременных сессий устройств
2. Декодирует диалекты протоколов в устойчивую модель (ТС / ТИ / СОЕ / команды)
3. Хранит архив, аварии и идентичность (адрес канала, общий адрес ASDU, метка актива)
4. Отдаёт HMI / API / мобильные экраны без БД на каждой плате
5. Обеспечивает auth, аудит и безопасный путь команд (выбор → исполнение → отмена)

Без этого слоя каждая PCB тащит свой облачный демо-канал (MQTT JSON, портал вендора). Это не масштабируется между вендорами, NAT и сменой 4G-адресов. Идентичность должна жить в кадре (`A` + `CA`), а не во временном IP.

## Зачем поверх нужен IoT-приложение

Здесь IoT — это **операционный IoT**, не бытовая электроника:

- Постоянная телеметрия с распределённых активов
- События со временем (СОЕ), переживают обрывы связи
- Команды и параметры с человеческой ответственностью
- Обзор парка: online / offline, диалект, последний общий опрос, последняя авария
- Внешние интеграции: REST / WebSocket / выгрузка в MES, ГИС, наряды

Хост — место встречи верности OT-протокола и IT-доставки. Плата остаётся лёгкой. Политики, хранение и UX — на сервере завода или в облаке.

## Почему основной язык — C#

| Потребность | Чем помогает C# / .NET |
|---|---|
| Долгоживущий сервис Windows / Linux | .NET Worker + ASP.NET Core, один язык |
| Работа с двоичным протоколом | Структуры, `Span<byte>`, endian-хелперы, меньше GC на горячем пути |
| Параллельные сокеты | `async`/`await`, Channel, пул потоков I/O |
| Десктоп для эксплуатации + Web API | WinForms / WPF / Avalonia **и** Minimal APIs в одном стеке |
| Строгая типизация ASDU / TI / COT | Enum, record, анализаторы ловят ошибки кадрирования рано |
| Развёртывание на ПК станции | Self-contained publish, Windows Service, IIS / Kestrel |
| Экосистема | Npgsql / SQL Server, Serilog, OpenTelemetry, зрелые IDE |

**Кратко о преимуществах**

1. **Один стек — много поверхностей** — демон сбора, HTTP mid-layer, десктоп-монитор, симулятор делят модели и библиотеки.
2. **Достаточная производительность для OT** — современный .NET сопоставим с Go/Java на сокет-серверах; GC настраивается; Native AOT возможен позже.
3. **Безопаснее чистых скриптов** — nullable, статический анализ и типизированные кадры снижают тихие ошибки, типичные для PowerShell/Python-прототипов.
4. **Удобно для эксплуатации на станциях** — многие промышленные Windows уже умеют .NET; установщики и службы привычны энергетикам.
5. **Кадры и долговечность** — C# / .NET остаётся мейнстримом enterprise с LTS и понятным апгрейдом.

Python / JS полезны для утилит и части UI. **Ядро хоста** (слушать → декодировать → писать → командовать) остаётся на C#, чтобы инварианты жили в одном компилируемом месте.

## Целевая схема (продукт, не копия старого проекта)

```
[ Полевая PCB / FTU ] --TCP--> [ Upper-Class Host ]
                                  |-- сессия + авто-детект диалекта
                                  |-- архив / realtime-хранилище
                                  |-- auth + роли
                                  +-- Web / API / консоль эксплуатации
```

Не-цели этого intro-репозитория:

- Не выгружать существующий код станции
- Без учётных данных вендоров, VPN и боевых endpoint’ов
- Без заявления, что облачное MQTT-демо заменяет хост верхнего уровня
