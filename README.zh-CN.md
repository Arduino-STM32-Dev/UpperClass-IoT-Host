# 工业物联网上位机（Upper-Class Host）

本仓库是一份**私有设计说明**，介绍位于现场设备之上的**上位机**（监控主机）产品方向：把 OT 原始报文变成可运维、可展示、可下发的厂站数据。

本仓库只说明主机层方向，**不**文档化、不 fork、不暴露任何既有现场工程。

**语言：** [English](README.md) · [中文](README.zh-CN.md) · [Русский](README.ru.md)

## 为什么需要上位机

现场板卡、FTU、PLC、传感器走串口或 TCP 上的短二进制帧。运维人员不直接读这些帧。上位机是主控室侧，负责：

1. 接纳大量并发设备会话
2. 把协议方言解码成稳定对象模型（遥信 / 遥测 / SOE / 遥控等）
3. 落库存档、告警与身份（链路地址、公共地址、资产标签）
4. 提供 HMI / API / 移动端视图，而不把数据库塞进每块板
5. 落实鉴权、审计与安全命令路径（选择 → 执行 → 终止）

没有这一层，每块 PCB 各自接一套云演示（MQTT JSON、厂商门户）。跨厂商、NAT、4G 地址漂移时无法规模化。身份必须在帧内（`A` + `CA`），不能依赖临时 IP。

## 为什么还要做物联网应用

这里的物联网指**运行物联网（Operational IoT）**，不是消费电子：

- 广域资产持续上送遥测
- 带时标事件（SOE）在断线重连后仍可追溯
- 带人责的遥控与参数闭环
- 车队视图：在线 / 离线、方言、最近总召、最近告警
- 对外集成：REST / WebSocket / 导出到 MES、GIS、工单系统

上位机是 OT 协议保真与 IT 交付的交汇点。板端保持精简；策略、存储与交互放在云端或厂站服务器。

## 为什么主语言选 C#

| 需求 | C# / .NET 适配点 |
|---|---|
| 长期运行的 Windows / Linux 服务 | .NET Worker + ASP.NET Core，同一语言 |
| 二进制协议处理 | 结构体、`Span<byte>`、端序工具，热路径少 GC 抖动 |
| 并发套接字 | `async`/`await`、Channel、线程池 I/O |
| 桌面运维工具 + Web API | WinForms / WPF / Avalonia **与** Minimal APIs 同栈 |
| ASDU / TI / COT 强类型 | 枚举、record、分析器尽早抓住组帧错误 |
| 厂站 PC 部署 | 自包含发布、Windows 服务、IIS / Kestrel |
| 生态 | Npgsql / SQL Server、Serilog、OpenTelemetry、成熟 IDE |

**优势摘要**

1. **一栈多用** — 采集守护、HTTP 中间层、桌面监控、联调模拟器共享模型与库。
2. **OT 够用的性能** — 现代 .NET 在套接字服务上可与 Go/Java 竞争；GC 可调；后续可选 Native AOT。
3. **比纯脚本更安全** — 可空性、静态分析、类型化协议帧，减少 PowerShell/Python 原型里的静默组帧错误。
4. **贴合厂站运维** — 大量工控 Windows 环境已具备 .NET 能力；安装包与服务对电力运维熟悉。
5. **人才与寿命** — C# / .NET 仍是主流企业语言，有 LTS 与清晰升级路径。

Python / JS 仍适合工具与部分 UI。**核心主机路径**（监听 → 解码 → 落库 → 命令）保持 C#，让不变量落在一个可编译的地方。

## 目标形态（产品方向，不是既有工程拷贝）

```
[ 现场 PCB / FTU ] --TCP--> [ 上位机 Upper-Class Host ]
                                |-- 会话 + 方言自动识别
                                |-- 档案 / 实时库
                                |-- 鉴权 + 角色
                                +-- Web / API / 运维控制台
```

本介绍仓库的非目标：

- 不倾倒既有厂站代码
- 不含厂商凭据、VPN 账号或线上地址
- 不主张第三方云 MQTT 演示可替代上位机
